   - Δ = 方法 − 对手，取 50 对的均值。10000 次按对重抽，各对手共用同一组重抽。

     - 拒绝 H0: Δ ≤ +.005 → **优于**；

     - 拒绝 H0: Δ ≥ −.005 → **劣于**（P5）；
     - 其余 → **无法下结论**。

## 4. 假设与判定

### 4.1 量

- 第 i 对（i = 1..50，按 holdout_B_pairs.tsv 去掉表头后的行序）、臂 a 的 seg35 记 S_{a,i}，seg4 记 G_{a,i}。
- 对比较对象 k：Δ_{k,i} = S_{方法,i} − S_{k,i}（seg4 同理），Δ̄_k = (1/50) Σ_i Δ_{k,i}。正值表示方法好。
- 统计量取均值。另报中位数、方法胜的对数、双侧 Wilcoxon 符号秩 p 值，只描述。

### 4.2 主假设

> **H_B**：在 B 线留出集 50 对上，方法 `Hx24-RF05-F1200-v4-C3`（含退路的方法级输出）的 seg35（本仓库口径）均值，比主族的每个比较对象都高出 ROPE 上沿（Δ̄_k > +.005）。主族是：配置 C、ANTs SyN `-t s`、FireANTs Greedy、FireANTs SyN、ConvexAdam-v4seg。

每个比较对象各得一个判定，逐个报告，不合成"对全部对手都优于"一句结论。

### 4.3 重抽（P13）

- **按对重抽**：
  - `rng = numpy.random.default_rng(20261107)`，每次 `idx = rng.integers(0, 50, 50)`，共 B = 10000 次；
  - 每次算 Δ̄*_{k,b} = mean(Δ_{k,idx})。
- **共用同一组重抽**：所有比较对象、seg35 与 seg4、各描述终点都用同一串 idx。
- **判定只用 p 值**。区间只作展示：用 numpy.percentile 的默认 method（'linear'）取 2.5、97.5 百分位，不做调整。两种写法只在边界计数上可能差 1。
- DSC30 这类全集的量，每次重抽后在被抽中的对上整体重算。

### 4.4 判定与 Holm（P5、P12）

**判法的来历**：
- 总负责人 11-07 约 11:45 AM 提案："差值（方法 − 对手）的受试者分块 95% 区间下界 > +.005 判优于；区间整个落在 ±.005 之内判相当；其余无法下结论；Holm"。原文补记在 decision_log，main b0c4577。
- BZ 约 11:48 AM 回"B3 同意"。
- 95% 即单侧 .025。"劣于"是 BZ 4:50 PM 采纳的补充（P5）。

对每个比较对象 k，算三个单侧自助 p 值（加 1 修正）：
- p^sup_k = (1 + #{b : Δ̄*_{k,b} ≤ +.005}) / (B + 1)：检验"优于"（H0: Δ ≤ +.005）；
- p^eq_k = max(p^lo_k, p^hi_k)：检验"相当"（TOST），其中 p^lo_k = (1 + #{Δ̄* ≤ −.005}) / (B + 1)，p^hi_k = (1 + #{Δ̄* ≥ +.005}) / (B + 1)；
- p^inf_k = (1 + #{b : Δ̄* ≥ −.005}) / (B + 1)：检验"劣于"（H0: Δ ≥ −.005）。

**Holm（步降）**：
- 三类各自在主族的 m = 5 个比较对象上做，单侧 α = .025。
- Holm 调整后的 p 值 p̃_(j) = max_{i ≤ j} min(1, (m − i + 1)·p_(i))，p̃_(j) ≤ .025 即拒绝；遇到第一个不过就停。
- Holm 的次序与各步只由意向处理（主分析）的 p 值决定；第 4.5 节的 S1 条件只降级某个对手的结论，不改 Holm 的步降。

**判定**：
- Holm 拒绝 sup → **优于**；
- Holm 拒绝 eq → **相当**；
- Holm 拒绝 inf → **劣于**；
- 都不拒绝 → **无法下结论**。

四类互斥。

**对应与报告**：
- m = 1 时，p^sup ≤ .025 等价于（除边界计数外）"95% 百分位区间的下界 > +.005"。
- 报告每个 k 的未调整 95% 区间、p 值、Holm 调整后的 p 值和步序。

**错判率**：
- 每一类在主族内的族错误率 ≤ .025。
- 同一对手，"优于"或"相当"出错的总概率 ≤ .05；加上"劣于"≤ .075。

**族**：
- F1：主终点 seg35，主族 5 个对手；
- F2：seg4，同样 5 个对手，单独一族，结论单列为"关键次要"；
- F3：官方 Dice35、描述臂与 90 s 档，只报未调整区间，**不判**；
- F4：PQ，单独一族（第 4.7 节）。

族与族之间不再校正，主结论只来自 F1。配置 C 不单独守门（P2 选 (a)）。

### 4.5 失败与退路怎么进统计（P11）

**方法臂**：

**无输出的原因**，每个没有输出的 (臂, 对) 记一类：
- (1) 方法自身：报错退出、导出不全，或配置 C 没有通过证书的状态；

### 5.3 机器纪律与存放（P4 = (a) + (d)）

- 一次只跑一个原生规模的作业。GPU 臂与 CPU 计时臂不同时跑；第 5 步的复核证书单元是 CPU 作业，也不与计时臂同跑。
- 每个单元启动前：
  - `systemctl --user list-units --all 'seq-vp-*' 'tag-*'` 显示没有别的作业在跑；
  - GPU 空闲；
  - MemAvailable ≥ 6 GB；
  - 负载门照 HE。
- 单元名用 `tag-hb-` 前缀。
- **存放**（CLAUDE.md 机器一节 BZ 11-07 的例外）：
  - HI 的输出在 /home（写死）；
  - 其余留出集运行的大文件写到 D 盘的专用目录（路径由留出集工具包定，例如 /mnt/d/seq_vp_tag_holdout_B_v1/），D 盘留 40 GiB 余量；
  - 小文件与记录留在 /home/rmcfz/seq_vp_tag_results/holdout_B_v1/。
  - 新根；启动过单元的根不再用。D 盘上只写这个专用目录。
- **计时运行在 /home 上跑**（定稿新增，〔推断〕的理由，由工具包实现）：
  - 方法臂、配置 C 臂、外部各臂的工作目录放在 /home（ext4），跑完、清单写好之后，再把要留的大文件移到 D: 的专用目录，移动前后各记 sha256。
  - 理由：D: 经 WSL 的 drvfs 写盘，〔推断〕比 ext4 慢。配置 C 有 90 s 墙钟预算，它的提交文件写得慢，就等于少给它算力，对它不公平；方法的修复有 1200 s 保险丝，也受影响。
  - 这样 C: 一侧要有一份运行中的临时空间：配置 C 单次约 5.5 GB，其余各臂每次不到 1 GB。
- 每个大批次开跑前重读 `df -h /home /mnt/c /mnt/d`。两侧守卫：
  - C: 一侧的需要量 + 15–20 GiB 门槛 ≤ C: 可用 + VHDX 可复用；
  - D: 一侧的需要量 + 40 GiB ≤ D: 可用。
  - 不满足就 STOP，交 BZ。**不临时启用 (b) 的额外删除**（删 probs36、删外部臂的 own_warped），BZ 没有选 (b)。
- **每次运行只留终态场与小文件**（CLAUDE.md 的常规规则）：
  - 中间文件在运行审核、记 sha256 之后删：配置 C 的中间提交（单次约 5.5 GB）、外部基线的大中间文件（BL2 Amendment 3 第 5 条；own_warped.npz 照 BL2 保留）、方法的 certified.npz 与 field_0600.npz（时机见第 5.2 节）；
  - **失败的运行与走退路的对一律全留**；
  - 只删本项目自己生成的文件。

### 5.4 失败与补跑（照 HI §3.2 的写法）

- **方法失败**（HE 内部的分类）：走退路，不重跑。子进程被 OOM 或 RuntimeMaxSec 杀掉，算方法失败。
- **hx_provenance_rejected**：批次 STOP，交总负责人与 BZ（P20）。第二次运行要有补跑记录，并披露。
- **外部基线与配置 C 臂的方法失败**：记录、保留，接着下一对，不重跑。
- **基础设施失败**：
  - 包括：机器重启、内核 OOM 杀掉单元、dxg `create_allocation failed`、磁盘守卫触发、监督进程被信号结束、driver 的内存守卫与 step exit −9、precheck 等满 15 分钟不过；
  - 发生时：批次 STOP，证据保留，交 BZ。
  - **补跑只能经一份显式的补跑记录**：
    - 由 BZ 或"lead on BZ's behalf"写，含原话、时间、原因，已提交；
    - 只补没有完整记录的对；
    - 每次失败的运行至多补跑一次；
    - 补跑与首跑连成一条链；
    - 补跑写自己的一次性锁。
  - 补跑又因基础设施失败：记"无输出（基础设施）"，不再有第三次运行。
- **"完整记录"的定义**：
  - 方法：line.json 与判定证书都写成；
  - 配置 C：classify_run 的类与候选记录写成；
  - 外部：result.json 与导出核对写成。
- 任何失败的判别都不读真值、不看精度。第 5.2 节第 11 步之前，没有一个精度数存在。

## 7. 它证伪不了什么

1. **一次抽样**：
   - 每对每臂只跑一次；方法的修复在 GPU 上不逐位可复现（C22.6）。v4 + C 的重复性只有 HE2 冒烟里与 P3 同一对差 2e-5 这一次（开发集一对）。
   - ANTs 不固定种子。
2. **整条流程的比较**：对配置 C 的差同时含分割器通道、T88、修复、C、退路，分不开；D82 = -a，留出集上没有 C 的消融。
3. **调参不对等**：方法的超参数在开发集上选过，外部基线零次调参。"优于"只能说"优于这些冻结配置下的基线"。
4. **只有 OASIS**：同一来源、同一预处理；跨数据集的泛化没有检验。
5. **Dice 量的是与 FreeSurfer 标签的一致**：方法的分割器就是学这些标签的；同类对手 ConvexAdam-v4seg 用同一个分割器，才把"配准好"与"分割器好"分开一部分。
6. **"相当"几乎达不到**：
   - 50 对时，95% 半宽约 .277 s。m = 1 时要 s < .018；Holm m = 5 的第一步要 s < .0137；补成恒等的对会把 s 撑大。
   - 〔估算〕判"优于"在 Holm 第一步要 Δ̄ > .005 + 2.58·s/√50：s = .01、.02、.03 时分别约 .0086、.0123、.0159。
   - "无法下结论"不等于"一样好"。
7. **只看均值、只看 seg35 / seg4**。
8. **时间不对等，也不同时**：
   - 方法约 221 s 加 U-Net，FireANTs 约 3–9 s，配置 C 90 s；90 s 档不是与方法等时。
   - 按臂跑约 32 h，机器状态会漂移；没有计时金丝雀（P21），各臂的时间不能严格互比。
   - 计时运行在 /home 上跑，移到 D: 不计入时间。
   - Pareto 图上没有正则权重的扫描。
9. **证书**：方法的输出全单元 J > 0 是认证过的，它说明的是可逆性，不是精度；对手的折叠只描述。
10. **退路的对**：方法走退路一时输出就是配置 C，那里的差只是噪声。
11. **"贝叶斯"**：留出集不检验后验与形变不确定度；C 只有开发集上不劣的读数；PQ 检验的是误差定位能力（F4）。
12. **上游的重复性**：HI 推断与 Atropos 在留出集上能否逐位重现，没有量。
13. **不与文献数字比**：主终点是本仓库 seg35，与 Learn2Reg 的官方 Dice 不是同一个函数。
